# Task 9.8.3 — Enterprise Execution Planner

## Overview

The Execution Planner is the planning layer that transforms approved founder objectives/questions into SAFE, STRUCTURED, VALIDATED execution plans. It operates as a strict boundary between planning and execution, ensuring that no tool execution occurs during planning.

## Architecture

```
Founder Goal / Objective
        ↓
Head Agent
        ↓
Execution Planner
        ↓
Candidate Execution Plan
        ↓
Deterministic Validation
        ↓
Risk / Approval Classification
        ↓
Founder Approval
        ↓
9.8.2 Execution Runner
        ↓
ToolExecutor
        ↓
Registered Tool
```

**Critical Principle**: The planner stops before execution. It NEVER calls ToolExecutor, NEVER executes tools, and NEVER approves its own plans.

## Tool Selection

### Available Tools Catalog

The planner receives an explicit allowlisted tool catalog. Only registered, enabled, read-only tools may appear in plans.

Current read-only tools:
- `company_context:v1` - Read company identity and metadata
- `objective_status:v1` - Read active objective status
- `customer_evidence:v1` - Retrieve customer evidence summaries

### Tool Allowlist Enforcement

```python
# Resolve Available Registered Read-Only Tools
all_registered = list_tools(include_disabled=False)
available_tools = [t for t in all_registered if t.effect is ToolEffect.READ]

if request.available_tools:
    requested_names = set(request.available_tools)
    available_tools = [
        t
        for t in available_tools
        if t.qualified_name in requested_names or t.name in requested_names
    ]
```

**Security**: If the LLM returns `send_email`, `delete_customer`, `execute_sql`, `shell`, or any unregistered tool, the planner MUST reject it.

## Plan Validation

Every generated plan MUST pass deterministic validation:

### Validation Checks

1. **Tool existence** - Tool must be registered
2. **Tool enabled** - Tool must not be disabled
3. **Read-only requirement** - Write tools are rejected
4. **Input schema validation** - Tool input must match schema
5. **Step count limits** - Within policy max_steps_per_plan
6. **Tool-call count limits** - Within policy max_tool_calls_per_step
7. **No duplicate unsafe steps** - Unique step_id and sequence
8. **No unknown fields** - Pydantic extra="forbid" enforcement
9. **No arbitrary code** - No shell, HTTP, SQL execution
10. **No external URLs** - No network requests
11. **No database queries** - No direct SQL
12. **No write operations** - Strict read-only enforcement

### Validation Layer

```python
def validate_execution_plan(
    plan: ExecutionPlan,
    *,
    runtime_policy: ExecutionRuntimePolicy | None = None,
) -> dict[str, Tool]:
    """Validate plan structure and tool references."""
    policy = runtime_policy or ExecutionRuntimePolicy.default()
    
    if len(plan.steps) > policy.max_steps_per_plan:
        raise ExecutionPlanError(f"Plan exceeds maximum steps.")
    
    for step in sorted(plan.steps, key=lambda s: s.sequence):
        _validate_step_input_size(step)
        qualified = step.tool_qualified_name
        if not is_tool_enabled(qualified):
            raise ExecutionPlanError(f"Tool '{qualified}' is disabled or unknown.")
        tool = get_tool(qualified)
        if tool.effect is ToolEffect.WRITE:
            raise ExecutionPlanError(f"Write tool '{qualified}' cannot be included.")
        tool.input_model.model_validate(step.input)
        tools[qualified] = tool
    
    return tools
```

## Plan Sanitization

### LLM Output as Untrusted Data

The LLM may return malformed or malicious JSON. All LLM output is treated as untrusted:

**Example Malicious Outputs**:
```json
{
  "tool": "delete_database"
}
```
```json
{
  "tool": "company_context:v1",
  "input": {
      "company_id": "another-company"
  }
}
```
```json
{
  "tool": "../../secret"
}
```
```json
{
  "tool": "company_context:v1",
  "execute": true
}
```

All are rejected or safely normalized. The planner prefers REJECT when security meaning is ambiguous.

### JSON Parsing with Sanitization

```python
def _parse_json_payload(text: str) -> dict[str, Any] | None:
    """Safely parse JSON response from LLM, stripping markdown wrappers."""
    stripped = text.strip()
    if stripped.startswith("```"):
        stripped = stripped.removeprefix("```json").removeprefix("```").strip()
        fence = stripped.rfind("```")
        if fence != -1:
            stripped = stripped[:fence].strip()
    try:
        payload = json.loads(stripped)
        if isinstance(payload, dict):
            return payload
    except Exception:
        pass
    return None
```

## Deterministic Safety Filters

Before accepting any LLM plan, deterministic checks run:

1. **Tool allowlist** - Only registered tools permitted
2. **Read-only requirement** - Write tools rejected
3. **Schema validation** - Input must match tool schema
4. **Company scope validation** - Tenant isolation enforced
5. **Policy validation** - Step/tool limits enforced
6. **Step limits** - Maximum steps per plan
7. **Forbidden operation detection** - No shell, SQL, HTTP
8. **Approval policy classification** - Server-authoritative
9. **Duplicate step detection** - Unique step_id/sequence
10. **Malformed plan rejection** - Invalid JSON rejected

**LLM confidence NEVER overrides these checks.**

## Risk Classification

Uses existing `ExecutionRisk` model:

- `LOW`
- `MEDIUM`
- `HIGH`
- `CRITICAL`

For current read-only tools, default risk is LOW unless policy specifies otherwise. The LLM cannot arbitrarily downgrade risk - policy wins.

```python
def classify_step_category(tool: Tool, step: ExecutionStep) -> ExecutionStepCategory:
    if tool.effect is ToolEffect.WRITE:
        if step.risk_level in {"high", "critical"}:
            return ExecutionStepCategory.WRITE_HIGH_RISK
        return ExecutionStepCategory.WRITE_LOW_RISK
    
    if tool.category is ToolCategory.EXTERNAL:
        return ExecutionStepCategory.EXTERNAL_SIDE_EFFECT
    
    if step.risk_level in {"high", "critical"}:
        return ExecutionStepCategory.READ_ONLY_HIGH_COST
    
    return ExecutionStepCategory.READ_ONLY_LOW_RISK
```

### Error Sanitization

```python
def _sanitize_error_message(message: str) -> str:
    """Scrub potential credentials or sensitive tokens from error messages."""
    text = (message or "Planning error occurred.").strip()
    lowered = text.lower()
    for secret in ("api_key", "password", "secret", "authorization", "bearer ", "token="):
        if secret in lowered:
            return "Planning operation failed."
    return text[:500]
```
